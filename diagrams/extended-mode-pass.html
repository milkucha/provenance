The Extended‑Mode Pass

One trip through Step 3, run once per pass — now two driver‑script calls wrapping a single subagent that only ever touches whichever of four judgment slots are open.

Source: .claude/skills/simulate/SKILL.md, “Step 3 (extended mode)” Applies whenever a participant has a non‑empty routines array

Made every step clickable for its exact command and what it reads/writes (hover for a one-line summary first); broke “Write the scene” open into its own four /enact sub‑steps; corrected two things that had drifted from the live scripts — “Author the arc” is now the fallback path, not the normal one, since /character Step 8 authors an arc at character creation by default; and Phase C's last three items (safety net, log the pass, build_source_index.py) are the orchestrator acting after simulate_pass_resolve.py returns, not inside that one call. Also widened the spacing throughout so it reads as a flow diagram rather than a compacted list.

Redrawn 2026-08-13. A same-day rewrite folded the old hand‑relayed sequence (a subagent stringing 15+ separate script calls together itself, hand‑copying each result into the next call) into three phases: two calls the orchestrator makes directly, wrapped around one subagent dispatch. The hand‑relay was its own failure mode — a smaller model could misread or mistype a value crossing that many hops.

Every pass still runs the same mechanism underneath — the pairing, the gate, the dice — it's just no longer the subagent's job to thread the calls together one at a time. Phase A resolves everything decidable before a word is written; Phase B writes the scene and handles whatever's left for a model to decide; Phase C resolves what a pass leaves behind.

Exactly four places a model's judgment is the right tool — nothing else in a pass is the subagent's to decide:
  1. Name a newborn — a plausible blend of both parents' names.
  2. Author a freshly‑needed arc's topic, needs, context, and premise — the fallback path now, since /character Step 8 authors one at creation by default.
  3. Optionally name a specific rival in a contested‑and‑hinder scene.
  4. Write the scene itself — the only one of the four that's never skipped.

A few things the diagram compresses

Base mode (no routines on either participant) still skips this whole chain for a plain four-step loop: draw a pair, dispatch a scene, log it, check for deaths. It isn't drawn here since it doesn't branch, and the rewrite didn't touch it.

Every number this chain rolls against — the 5-scene reproduction threshold, the 15% contested odds, the 8-pass lead expiry — still lives in _lore/tuning.json, now read once, inside simulate_pass_brief.py itself, rather than by each of the old separate scripts.

An optional pregeneration step (Step 2h, only if asked for) can run -generate mode's own mechanical loop inline before Phase A ever starts, to grow the starting cast first — not drawn here since it's a separate, opt-in mode with its own shape.
