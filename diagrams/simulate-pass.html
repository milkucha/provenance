One Scene, Grounded — and the Loop That Repeats It

There is no more mode to pick. Against another character, /enact always requires routines+arc on both files and always runs the same scripted mechanical layer before the scene is written — no freeform fallback. /simulate is nothing but a loop around this one mechanism: draw a pair, dispatch one /enact scene, log it, repeat.

Redrawn 2026-08-27. Base mode is gone — there's no more fork. What used to be “extended mode” is now simply how /enact works against another character, full stop; a participant missing routines/arc now stops the run and points at /character to complete them, rather than silently falling back to a freeform scene. The mechanical block, the judgment slots, and the closing checks that used to live in /simulate's own file moved into /enact itself, which is why this diagram no longer branches: one linear path, with /simulate's own loop (pairing, lead‑override, bookkeeping) drawn as the thin wrapper it actually is around a single dispatched /enact scene. Also added the new death‑legacy roll and its apply step (/enact Step 8, points 6–7) and fixed routine_actions to read as an action progression, not a trait label.

Redrawn 2026-08-16. Made every step clickable for its exact command and what it reads/writes (hover for a one-line summary first); broke “Write the scene” open into its own sub‑steps; corrected two things that had drifted from the live scripts — “Author the arc” is the fallback path, not the normal one, since /character Step 8 authors an arc at character creation by default; and the closing checks (safety net, log the pass, build_source_index.py) are the orchestrator acting after the subagent returns, not inside one call. Also widened the spacing throughout so it reads as a flow diagram rather than a compacted list.

Redrawn 2026-08-13. A same-day rewrite folded the old hand‑relayed sequence (a subagent stringing 15+ separate script calls together itself, hand‑copying each result into the next call) into a handful of driver-script calls the orchestrator makes directly, wrapped around one subagent dispatch. The hand‑relay was its own failure mode — a smaller model could misread or mistype a value crossing that many hops.

/simulate's own job shrank to almost nothing: decide who's paired (uniform draw, plus a lead-override check that can redirect the pair toward someone carrying an unresolved thread from an earlier pass), dispatch one /enact scene, then log what came back and check nothing leaked into the real files. Everything that actually decides what happens in the scene — location, arc progress, reproduction, death, its legacy — lives in /enact now, the same whether it's dispatched here or run directly by an author against two characters they picked themselves.

Exactly three places a model's judgment is the right tool inside the mechanical layer — nothing else in a grounded scene is the subagent's (or author's) to decide:
  1. Name a newborn, and reword their inherited routine into their own action progression — a plausible blend of both parents' names, and a rewrite grounded in the child, not a copy-paste.
  2. Author a freshly‑needed arc's topic, needs, context, and premise — the fallback path now, since /character Step 8 authors one at creation by default.
  3. Optionally name a specific rival in a contested‑and‑hinder scene.

Writing the scene itself is a fourth, unconditional judgment call — the only one of the four that's never skipped.

A few things the diagram compresses

The eligibility-gate node (gateE) folds together two separate checks /enact Step 2 actually makes — routines non-empty, and arc populated — into one diamond, since both fail the same way (stop, name the missing field, point at /character).

build_source_index.py now runs unconditionally at the natural end of any /simulate batch, resolving an asymmetry the pre-2026-08-27 version of this diagram flagged: the old base-mode text never mentioned it at all, while extended mode's closing steps did. There's only one path now, so there's nothing left to be asymmetric about.

Every number the mechanical block rolls against — the 5-scene reproduction threshold, the 15% contested odds, the 8-pass lead expiry, the 40% death-legacy odds — lives in _lore/tuning.json, read via scripts/lore/tuning.py inside each script rather than hardcoded anywhere that needs to stay in sync by hand.

An optional pregeneration step (/simulate Step 2h, only if asked for) can run /generate's own mechanical loop inline before this per-pass sequence ever starts, to grow the starting cast first — not drawn here since it's a separate, opt-in command with its own shape, genuinely scene-less and linear (see .claude/skills/generate/SKILL.md).
